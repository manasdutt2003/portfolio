03
Week 03 Data Trust · SQL · LLM Insights

QuickMart Data Trust Pipeline

Three messy extracts, no clean version of the truth — and numbers the room won't argue with.

A grocery delivery business across four cities had three unreconciled systems and a leadership deck due Monday. This pipeline takes the files exactly as received and produces figures that tie every way they are cut — with every excluded, changed or questioned order counted, explained and traceable back to a received row. Same files in, same answer out, every time.

6,103Raw orders ingested
398Tests passing
₹7,756Commission leakage found
₹2.31MDelivered sales, reconciled
  • Deduplication that doesn't destroy evidence — whole-row copies, conflicting repeats, same-person customers and product repeats separated into four classes, applied in a defended order so genuine repeat purchases survive.
  • 12 validation rules (R01–R12) across customer, product, price, date, quantity and status, with strict and lenient populations compared and the delta defended row by row.
  • SQL ↔ Python parity tests — 96 SQL question files and the Python pipeline must agree, or the build fails.
  • LLM insights, verified not trusted — leadership prose drafted from aggregated mart JSON at temperature 0 / seed 42, then every drafted figure checked against a mart. The test suite plants a fake ₹9,999,999.99 and the verifier catches it.
  • An honest scorecard — 23 acceptance criteria verified live: 20 PASS, 2 PARTIAL, 1 FAIL, with what isn't done named explicitly rather than glossed over.

04
Week 04 Healthcare · Finance Recon · Audit

CloneStream Healthcare Data Crisis

Finance deadline Wednesday 5PM. Auditors on-site Friday. One command rebuilds everything in 18 seconds.

A hospital network found integrity problems across claims, visits and medical records, with an unexplained revenue gap and auditors arriving. This repository finds what broke, cleans the data, reconciles the money, plans the fix and packages the evidence — all as code, versioned, tested and reproducible. Delivered across five sprints, each on its own branch and tag.

$6.07MTies to the cent
441DQ rules run
349Tests
18sFull rebuild
  • Every claim dollar sits in exactly one bucket — paid $1.95M, adjustments $0.64M, denied $1.12M, under appeal $0.16M, pipeline $2.23M. They reconcile to $6,066,812.08 exactly, and the build fails if they don't.
  • Certain and estimated figures are never blended — $1,945,489 paid (certain) is reported separately from $1.17M expected recovery (range $1.04M–$1.30M).
  • The courage to say "not determinable" — the claim→bill link points at the wrong patient on 250 of 250 claims, so the over-charging question is declared unanswerable rather than answered precisely and wrongly.
  • Root cause, not symptoms — 14 hypotheses tested; the failure rate is statistically flat across all seven years (p = 0.96), proving a design gap rather than a recent incident.
  • Audit-ready by construction — 49 ingest validators, per-run logs, a SHA-256 fingerprint on every output, and make verify failing if a single file was edited.
  • Also ships: Slack threshold alerts, a scheduled Databricks job, a Power BI build guide, and memos for Finance, Compliance and Patient Care.

05
Week 05 AI Agents · MCP · Claude Code

Sales Sentinel & Agent Engineering

Two AI agents that check each other, with a hook-enforced boundary between them.

A three-day arc through AI-assisted engineering: structured LLM extraction, then a Claude Code sandbox with custom instructions, hooks and an MCP server, then a real product — Sales Sentinel, a ledger-first cleaning pipeline for daily retail sales CSVs that replaces a two-hour manual job with one command, built and maintained by a coder agent and a tester agent that are structurally prevented from doing each other's job.

180Tests · 95% branch
47/47Spec rules covered
90.4%Mutants killed
26/26Boundary cases held
  • Every input row gets exactly one fate — recorded in row_ledger.csv. Rows and money must reconcile or the run fails. Nothing is silently dropped by a dropna().
  • Content-replay detection — deduping on ID finds zero duplicates here; replay detection finds 70, reported as bursts with their revenue impact and a switchable policy.
  • Hook-enforced agent boundary — the tester writes tests from the spec and can never touch src/; the coder writes code and can never touch tests/. Ask the coder to "just fix the failing test" and the guard denies it and logs the attempt.
  • A local MCP server gives both agents real data-quality tools, plus a domain skill the agents load automatically.
  • Decimal money with half-up rounding, hierarchical median imputation after dedupe, four DAMA quality dimensions, and exit codes 0/1/2/3 for schedulers.
  • Days 1–2 — a hardened invoice-extraction prompt that returns parse-safe JSON every run, and a sandbox exploring CLAUDE.md, hook exit-code semantics and a FastMCP text-tools server.
